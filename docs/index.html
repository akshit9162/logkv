Recovery

  1. 01

    Replay from offset 0

    Each record is checked for structure and checksum.

  2. 02

    Stop at the first bad record

    What follows is a torn tail from a crash mid-append.

  3. 03

    Truncate to the last good offset

    A partial write surfaces as absence, never as garbage.

  4. 04

    Verify on every read

    The index says where a record is, not that its bytes are still good.

Killed mid-append

A process crash, not a power cut: SIGKILL leaves the page cache intact, so this checks ordering and recovery, not media durability. Torn tails are tested by truncating the log mid-record.

The writer prints an index after every put() that returns, then dies by SIGKILL. The verifier checks every acknowledged write.

One more recovered than acknowledged is correct: it landed before the acknowledgement printed.

Scope

  • Single node, single writer, no locking.
  • The index lives in memory; recovery replays the whole log. A hint file is next.
  • Compaction is stop-the-world, then rename(2) and an fsync of the directory.
  • A bad record mid-log is treated as a torn tail: everything after it is dropped.
