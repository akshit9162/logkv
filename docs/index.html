What does durability cost, and what survives a crash?

A crash-safe, append-only key-value store in C++20, built to answer one question with a number instead of an opinion: what is actually guaranteed when a write returns? Every record is CRC-protected, a torn tail from a crash is detected and discarded, and a SIGKILL harness checks that no acknowledged write is ever lost.

How it works

One log, one index, one rule on recovery

Every mutation is appended to a single log file as a self-describing record. An in-memory hash index maps each key to its latest record and is rebuilt by replaying the log at startup.

01put / eraseAppend a record: CRC32 · type · klen · vlen · key · value
02IndexKey → offset of its latest record
03SyncNone / Batched / Always, set explicitly
04getRead at offset, verify the CRC again
05open()Replay; stop at the first bad record, truncate the torn tail
06compact()Rewrite live keys, rename(2), fsync the directory

The checksum covers the length fields too, so a corrupt klen can't be used to mis-parse the rest of the log. A torn record ends replay and is truncated, so a partial write surfaces as absence, which callers already handle, instead of garbage.

On macOS, fsync() isn't durable. It only reaches the drive's write cache; F_FULLFSYNC asks the drive to flush to media, about 2.2 ms per write. A store claiming six-figure "durable" writes per second on a laptop is measuring the cache.
Proving the guarantee

Kill it mid-write, then check

tools/crashtest.sh runs a writer and sends it SIGKILL at an unpredictable point inside an append: no destructor runs and no buffer is flushed. The writer prints an index after every put() that returns; the verifier then asserts every acknowledged write is present with the right value.

round 3: PASS  acked=115 present=115 missing=0 wrong=0 recovered=116 truncated=0
round 4: PASS  acked=223 present=223 missing=0 wrong=0 recovered=224 truncated=0
all rounds passed: no acknowledged write was lost
recovered = acked + 1 is correct. One record landed but the process died before acknowledging it. An acknowledged write is never lost; an unacknowledged one may survive. The reverse would be the bug.

Torn tail

Bytes chopped off the log: earlier records survive, the partial record is discarded, the file is truncated to the last good offset.

Bit flip

A single flipped bit inside a committed record is caught by the CRC instead of being returned to the caller.

Sanitizers

ASan and UBSan run in CI on Linux; UBSan is also clean locally on macOS.

Honest scope

What it isn't

Single-threaded

One writer, no internal locking.

In-memory index

The key set must fit in RAM; values stay on disk.

O(log) recovery

Replays every record. Next: a hint file on compaction.

No range scans

A hash index, not an LSM tree. Next: memtable + SSTables.
